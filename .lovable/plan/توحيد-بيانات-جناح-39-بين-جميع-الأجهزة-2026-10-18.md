# توحيد بيانات جناح 39 بين جميع الأجهزة

## 1. نتيجة فحص التخزين الحالي

**في السحابة الآن:** بيانات المريض الأساسية فقط، بما فيها ملاحظته العامة وحالة الخروج وملاحظة الخروج. صور البطاقة المدنية موجودة في تخزين خاص وبيانات ربطها مرتبطة برقم الملف. الحسابات والموافقات والأدوار والمحادثات موجودة أيضًا؛ المحادثات تخص صاحب الحساب وليست سجلات مشتركة.

**غير موجودة في السحابة:**
- العلامات الحيوية: التاريخ والوقت والضغط والنبض والتنفس والحرارة والأكسجين والوزن.
- ملاحظات التمريض المؤرخة، وسجلات تسليم SBAR.
- خطط الرعاية: المشكلة والهدف والتدخلات وتواريخ التعرف والحل والتوقيع.
- الجولات: النتائج والأوامر والطبيب والممرض والتاريخ.
- سجلات إعطاء المهدئات: الدواء والجرعة والطريقة والسبب ومن أعطاه والأثر والتاريخ والوقت.
- توزيعات التمريض المحفوظة: المريض والممرض والوردية والملاحظات، وقائد الفريق المحفوظ لكل تاريخ ووردية.
- تاريخ الدخول والخروج المتكرر: سجلات الإقامة السابقة وملاحظات خروجها؛ السحابة تحتفظ فقط بحالة الخروج الحالية على المريض.
- سجل الأدوية الكبرى/المراقبة: التصنيف والدواء والتركيز/التكرار ورقم الوصفة وصفوف أسماء المرضى والمدة.
- المرضى بلا رقم ملف: المزامنة الحالية تستبعدهم بالكامل.

**بيانات لا تُحفظ أصلًا بشكل دائم:** بعض اختيارات التوزيعة والطباعة والنماذج تبقى في الصفحة فقط. سنحفظ البيانات السريرية المشتركة ضمن سجلاتها؛ تفضيلات العرض الشخصية كحجم الخط واتجاه الطباعة واللغة تبقى للجهاز. لا توجد حاليًا جداول منفصلة لكل نموذج ورقي؛ كثير من الأوراق تُشتق من بيانات المريض والسجلات أعلاه.

**المشكلة الحالية:** المزامنة تسحب المرضى مرة عند التشغيل، ثم ترفع القائمة المحلية كاملة؛ وقد تحذف مرضى السحابة غير الموجودين على الجهاز. لا يوجد تحديث حي أو طابور موثوق أو سجل تعارضات. لا توجد جداول المشروع ضمن نشر Realtime حاليًا. نسخة JSON اليدوية تشمل خمسة أنواع فقط؛ نسخة اللابتوب أوسع لكنها ليست مزامنة.

## 2. النتيجة المطلوبة

السحابة هي المرجع النهائي لكل البيانات السريرية المشتركة، وذاكرة الجهاز نسخة للعمل دون إنترنت. تسجيل الدخول ونظام الموافقات يظلان كما هما. الموظفون المعتمدون يشاهدون نفس السجلات على الهاتف والمتصفح واللابتوب.

## 3. الجداول والروابط — تفاصيل تقنية

- المرضى: الاحتفاظ بمعرّفات UUID السحابية الحالية، وإضافة إصدار وتاريخ حذف ومعلومات تحديث موثوقة. دعم رقم ملف اختياري بحقل جديد مع إبقاء أعمدة التوافق القديمة؛ لا نعرض أي مفتاح توافق داخلي باعتباره رقم ملف حقيقيًا.
- جداول مرتبطة بـ `patient_id UUID`: `patient_vitals`, `patient_nurse_notes`, `patient_sbar`, `patient_care_plans`, `patient_rounds`, `patient_tranquilizer_events`, `patient_admissions`, `staff_assignments`.
- `medication_register`: حفظ تعريفات الأدوية وصفوفها مع رابط مريض اختياري، والإبقاء على النص القديم عندما لا يمكن تحديد المريض بثقة.
- `ward_shift_settings`: قائد الفريق وتفاصيل التوزيعة لكل تاريخ ووردية؛ `ward_settings` للإعدادات المشتركة الفعلية فقط، وليس كلمات المرور أو الجلسات أو تفضيلات الجهاز.
- ربط البطاقة: إضافة ربط UUID إلى بيانات المستندات، مع الاحتفاظ بالروابط القديمة والصور الموجودة؛ دعم سجل مستندات UUID جديد عند الحاجة لتجاوز قيد المفتاح القديم على رقم الملف، دون إسقاط الجدول القديم أو إعادة رفع الصور.
- صفحات المريض وروابط الطباعة تستخدم UUID عند مشاركتها بين الأجهزة؛ تبقى الأرقام المحلية القديمة قابلة للتحويل على جهازها فقط، ولا تُعامل كهوية مشتركة.
- `sync_history`: نسخ التعارضات والعمليات المهمة؛ `sync_operations` لمنع تكرار تنفيذ الطلب؛ `migration_runs` و`migration_record_map` لتتبع النقل وإعادة تشغيله بأمان.
- جميع الجداول المشتركة وسجل التعارضات: RLS مفعّل، وصول للموظف المسجل والمعتمد فقط عبر `is_approved`، مع صلاحيات صريحة. لا وصول عام أو اعتماد على حالة محفوظة بالجهاز لمنح صلاحية سحابية.

## 4. استراتيجية المزامنة والعمل دون إنترنت

1. كل تعديل يُحفظ مع عملية outbox داخل معاملة محلية واحدة؛ لا يُحذف الطلب قبل تأكيد حفظه بالسحابة.
2. خدمة واحدة تبدأ بعد التحقق من الحساب، تسحب البيانات على دفعات وتدفع العمليات بالترتيب، وتعيد المحاولة تلقائيًا عند العودة للإنترنت أو إعادة فتح البرنامج.
3. Realtime يخطر الأجهزة بالتغييرات؛ تُسحب السجلات المصرح بها وتُحدّث الذاكرة المحلية، فتتجدد صفحات Dexie الحالية وتُبطل ذاكرة الاستعلامات ذات الصلة. لا نعيد إرسال التغييرات المستقبلة كأنها تعديلات محلية.
4. فحص دوري بديل كل نحو 5 ثوانٍ أثناء الاتصال والنشاط، مع جلب تعويضي بعد الانقطاع/عودة التركيز، وترقيم صفحات ومؤشر تحديث موثوق يشمل الحذف.
5. مؤشر صغير: «متزامن»، «جارٍ المزامنة»، «غير متصل — N تعديلات معلقة»؛ فشل صلاحية أو مزامنة يُعرض بوضوح ولا يتحول إلى نجاح زائف.
6. التعديل غير المحفوظ داخل خانة مفتوحة لا يُستبدل بسبب تحديث بعيد؛ تظهر إشارة بوجود نسخة أحدث عند الحاجة.

## 5. التعارضات والحذف

- كل عملية تحمل UUID ثابتًا وإصدار الأساس والحقول المتغيرة. الحفظ السحابي ذري مع تحقق الإصدار وتسجيل العملية.
- دمج الحقول غير المتعارضة؛ عند تعارض نفس الحقل/السجل يفوز الأحدث وفق وقت تغيير موثق مع معالجة انحراف ساعة الجهاز وترتيب حاسم، وتُحفظ النسخة الأخرى في سجل خاص ويظهر تنبيه.
- السجلات القديمة التي لا تحمل وقت تعديل موثوق تُنقل دون استبدال قيمة سحابية مختلفة بصمت؛ يُحفظ الاختلاف للمراجعة.
- حذف منطقي `deleted_at` يصل لكل الأجهزة، ويشمل إخفاء سجلات المريض المرتبطة دون محو تاريخها. تعديل قديم لا يعيد مريضًا محذوفًا؛ الاستعادة تتطلب إجراءً صريحًا.
- الصور تبقى خاصة وعلى الإنترنت فقط؛ لا تُنسخ إلى outbox أو ملفات التصدير أو سجل نصي أو المساعد. حذف/استبدال الصورة يستخدم مسارًا موثوقًا خاصًا، لا حذفًا صامتًا عند انقطاع الاتصال.

## 6. النقل لمرة واحدة

1. حفظ نسخة محلية آمنة من السجلات الموجودة قبل النقل؛ لا نمحو البيانات المحلية قبل نجاحه.
2. إيقاف الرفع الشامل والحذف الحاليين، والتعبئة التلقائية القديمة وقاعدة الخروج المرتبطة بتعداد قديم؛ الأجهزة الجديدة تبدأ من السحابة لا من قائمة قديمة.
3. عند أول دخول متصل لموظف معتمد، نقل المرضى أولًا بمطابقة رقم ملف/CID بعد التطبيع، بمعاملة سحابية تمنع سباق جهازين. التعارض في الهوية يُعزل للمراجعة؛ لا دمج اعتمادًا على الاسم وحده.
4. نقل السجلات التابعة بعد تحويل روابط الأرقام المحلية إلى UUID. إعادة المحاولة لا تنشئ نسخًا؛ التطابق الكامل يُدمج فقط عندما يكون آمنًا، والاختلافات تُحفظ. المرضى بلا رقم ملف ولا CID يحصلون على UUID، وأي تشابه بين أجهزة مختلفة يُعرض للمراجعة بدل دمج تخميني.
5. ربط صور البطاقة بالسجلات المطابقة مع الحفاظ على مساراتها الحالية.
6. عرض ملخص قابل للمراجعة لكل جهاز: أُضيف / دُمج / يحتاج مراجعة / فشل مع إعادة محاولة. لا يمكن استرداد بيانات جهاز آخر حتى يفتح النسخة المحدثة متصلًا بحساب معتمد.

## 7. المخاطر والتحقق قبل التسليم

- النسخ القديمة قد تعيد رفع قائمة ناقصة أو حذف بيانات: تقييد الكتابة السحابية المباشرة القديمة، والحفظ الجديد عبر عمليات محمية؛ يلزم تحديث تطبيق اللابتوب أيضًا، تحديث الرابط وحده لا يحدّث ملف EXE.
- إعداد بناء اللابتوب الحالي يستبدل وظائف الدخول برسالة خطأ حتى عند الاتصال؛ سنوصل نفس نظام الدخول الحالي بمسار متصل مدعوم دون تغيير الحسابات أو طريقة الدخول، ونختبر الخروج وإعادة الفتح. هذه معالجة توافق لازمة لتحقيق المزامنة على اللابتوب، وليست إعادة تصميم للمصادقة.
- لا يمكن ضمان دمج سجلات قديمة بلا هوية أو وقت تعديل دون مراجعة؛ الأولوية لحفظ النسختين لا فقدهما.
- دون إنترنت تظل البيانات آخر نسخة وصلت للجهاز؛ لن تظهر التعديلات البعيدة قبل الاتصال. لا يمكن معرفة سحب الموافقة لحظيًا أثناء الانقطاع، لكن الاتصال يعيد التحقق ويوقف المزامنة غير المصرح بها.
- الصور تظل تحتاج إنترنت؛ لا وعد بمزامنتها أو طباعتها دون اتصال.
- اختبار بحسابين معتمدين وجهازين: إضافة وتعديل سجل من كل نوع، ظهور التغيير خلال ثوانٍ، فصل الشبكة ثم إعادة الاتصال، تعارض متزامن، حذف وعدم إعادة الظهور، نقل متكرر/متزامن، مريض بلا رقم ملف، وصور البطاقة والطباعة.
- اختبار رفض الوصول للحساب غير المعتمد، وعدم توسيع أدوات المساعد/‏MCP إلى السجلات الجديدة أو الصور، وعدم ظهور بيانات حساسة في السجلات التقنية.
- تحديث README وخطة المهام، والتحقق من توافق اللابتوب دون تغيير نظام الدخول. التغليف النهائي لحزمة Windows الجديدة خطوة تسليم مستقلة بعد نجاح الاختبارات.

**لا تغييرات على التطبيق أو قاعدة البيانات قبل الموافقة على هذه الخطة.**
